# Consistent learning context

Current web wording: v1.4.6, reviewed November 23, 2026.

The learning vocabulary is project management. Story props should not become an extra vocabulary test. Use these exact names in requirements, scope, work groups, budget headings, quality questions, feedback, and saved plans:

- **Clear path**: the accessible route through the Hero Hub.
- **Message desk**: the desk with low buttons for sending messages and a screen for reading them.
- **Quiet space**: a place to sit and rest away from noise.

`learning-content.js` defines the three parts, neighbor notes, work-list names, jobs, and acceptance checks. The game imports these names into its answer choices, budget headings, checks, and feedback. The stories also use the same names. Do not substitute nook, recharge nook, recharge station, signal desk, Gear, or a shortened group label.

The budget covers all three parts. The quality activity tests all three parts. The scheduling example builds the same Clear path used in the scope and work-breakdown lessons. Capacity is measured in hours, not invented work boxes.

Keep real learning terms such as operations, stakeholders, requirements, scope, acceptance criteria, work breakdown structure, dependencies, capacity, contingency reserve, kanban, WIP, just-in-time, jidoka, andon, error-proofing, change control, kaizen, PDCA, and handover. Explain them with common words and concrete examples.

After each learning activity, players choose between two complete story actions and see an immediate result. Do not add an inventory, tool requirements, supply-pack counters, city-upgrade gates, delivery-point arithmetic, or a second resource budget. The ending asks which neighborhood to visit first; all three are visited.

Budgets use tokens in the budget lesson. Capacity uses hours in the capacity lesson. Kanban replenishment uses boxes of pencils in its own practice. None is a currency spent across the adventure.

Old saved records receive wording updates without rebuilding their answers from an unfinished replay. Earlier quality completions are retained, but are not represented as having performed the new Quiet space check.

Saved plan summaries must describe the player’s tested choices, including choices that need repairs. Do not use a fixed successful-plan summary for risk, replenishment, printer, or finale activities. A kanban round sends available boxes first, then packs replacements for the next request; missed deliveries wait until tomorrow in this practice.

Story order: make the hub plan, budget for it, build it, then check it. Early route work uses drawings and job cards; the Quiet space is used after it is built. The optional landing pad changes the hub opening by two hours. The Signal Rover launch is the new project in issue 13. Activity captions must use the same units and names as the lesson. Saved review feedback belongs to the tested plan, never an unfinished replay.

Separate deliveries completed from buffer readiness: all six deliveries can be sent while the final buffer is empty. Report both. Budget records describe planned spending and reserve before the replacement test. Finale capacity describes available time explicitly; avoid phrases such as a person being full.

Incomplete-activity prompts must identify the missing action. An over-budget plan needs a lower cost, not more selections. A stopped printer still needs its holder fitted and tested. Choice reviews name the selected category and explain the concept. Open saved reviews when a choice needs correction; keep successful reviews collapsed.

Saving an experiment is different from adopting its change. Use Save our test results for the improvement activity; an ineffective change should not receive a positive work-system review. Read-aloud targets include current questions, choices, and story decisions without nested duplicate targets. Before a first result exists, navigate to Try it with a matching URL and a short explanation.

Result summaries name the actual missing needs, unwanted extras, overloaded helper and hours, or failed risk response. Do not count unwanted ideas as extra hub parts. Needs reviews state whether an item was added or left off. Change our plan preserves answers in editable activities; Try this activity again starts a fresh board, quality, or launch run while retaining the saved result.
